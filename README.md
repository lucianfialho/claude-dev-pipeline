# claude-dev-pipeline

**A skill corpus for Claude Code focused on the dev pipeline loop:
read an issue → deliver a PR.** Ships the same skill in two forms —
prose (`SKILL.md`) as the source of truth, and state machine
(`skill.yaml`) generated by [atomic-gates](https://github.com/lucianfialho/atomic-gates)'
offline converter.

Install this plugin alone and the skills work as normal Claude Code
skills — prose, prompt-driven, no dependencies. Install it alongside
[`atomic-gates`](https://github.com/lucianfialho/atomic-gates) and the
same skills run through a state-machine runtime with schema validation,
audit trail, and blocking gates on commit/PR.

> ⚠️ **Status: experimental.** This corpus is part of an exploratory
> implementation of Jesse Vincent's *[Rules and Gates](https://blog.fsck.com/2026/04/07/rules-and-gates/)*
> thesis. See the [end-to-end dogfood run](https://github.com/lucianfialho/atomic-gates/blob/main/docs/dogfood/solve-issue-run.md)
> in the atomic-gates repo for a full walk-through of the `solve-issue`
> orchestrator pipeline using this corpus.

## What ships

15 skills organized in four families, each in two formats:

**Orchestration**

| Skill | Purpose |
|---|---|
| `solve-issue` | Orchestrate reading a GitHub issue → implementing → testing → opening a PR |
| `batch-issues` | Process multiple issues in parallel via agent teams |
| `context-sync` | Update `.metadata/` knowledge base per directory |

**Specialists** (invoked by `solve-issue` for domain-specific implementation)

| Skill | Purpose |
|---|---|
| `backend-dev` | API, database, auth, server logic |
| `frontend-dev` | React/Next.js components, a11y, responsive |
| `qa-engineer` | Tests, edge cases, coverage |
| `ux-designer` | UX heuristics, accessibility, interaction |
| `code-reviewer` | Bugs, security, performance, quality review |

**Review**

| Skill | Purpose |
|---|---|
| `review-pr` | Review a PR with specialist passes (frontend, backend, security, UX) |
| `batch-review` | Run all applicable specialists in parallel with unified verdict |
| `validate-issue` | Verify a PR implementation covers every requirement from the linked issue |
| `check-security` | Focused security review — OWASP Top 10, secrets, auth, dependencies |
| `suggest-tests` | Analyze a diff and suggest missing tests, edge cases, regression risks |
| `ux-review` | UX-focused review — Nielsen heuristics, WCAG 2.1 AA |
| `pr-summary` | Generate structured PR summary — what changed, why, impact |

Each skill lives at `skills/<name>/` with:

```
skills/<name>/
├── SKILL.md      # the prose source of truth, hand-written
└── skill.yaml    # a state-machine skeleton generated from SKILL.md
                  # by atomic-gates' import_skill.py converter
```

The `skill.yaml` files are committed so users don't need to run anything
after install, and so anyone reading the repo can see the mechanical
output of the converter side-by-side with its prose source.

## Install

```bash
claude plugin marketplace add lucianfialho/claude-dev-pipeline
claude plugin install claude-dev-pipeline
```

Use any of the skills immediately:

```
/solve-issue 42
/review-pr all
/validate-issue
/check-security
/suggest-tests
```

This is the **prose mode** — skills run as Markdown via the native
Claude Code `Skill` tool. No runtime dependencies.

## Install with atomic-gates (recommended)

```bash
claude plugin marketplace add lucianfialho/atomic-gates
claude plugin install atomic-gates

claude plugin marketplace add lucianfialho/claude-dev-pipeline
claude plugin install claude-dev-pipeline
```

With both plugins installed, invoking a skill goes through the
atomic-gates runner. This adds:

- **Schema-validated output** at every state transition — the agent
  cannot advance without producing structured data that matches the
  state's declared shape
- **Run persistence** in `.gates/runs/<run_id>.yaml` with full history
  and the namespaced `skill_id` (`claude-dev-pipeline:solve-issue`)
- **Crash recovery** — a killed session can resume from the last state
- **Blocking gates on critical actions** — if `atomic-gates` is also
  configured with a `.gates/config.yaml` in your project, commits
  without updated `.metadata/` are blocked, PRs without a structured
  body are blocked, and writes outside specialist scope are blocked

The skill's `skill.yaml` is discovered automatically by atomic-gates
via cross-plugin discovery (added in atomic-gates v0.3.0).

## How the two formats stay in sync

The `skill.yaml` files are **generated** from `SKILL.md` by
atomic-gates' offline converter, not hand-written. The script
`scripts/regenerate-skill-yaml.sh` regenerates all of them in one pass:

```bash
./scripts/regenerate-skill-yaml.sh
```

The converter is intentionally dumb — it walks the markdown, extracts
every `## ` heading as a state, copies the section body as
`agent_prompt`, and emits a linear chain of transitions terminating in
`done`. Meta-headings like "Red Flags" or "Rules" are flagged with
`WARNING` comments so you know to prune them when refining.

**The current `skill.yaml` skeletons are first drafts.** They validate
against atomic-gates' schema and run, but they haven't been refined
with `output_schema` per state, `when` transitions, or pruned of meta
sections. Iteration is incremental: edit `skill.yaml` directly when
you want to promote a specific skill to a fully-enforced state machine.

## The pipeline, visualized

```
┌─────────────────────────────────────────────────────────┐
│ atomic-gates (runtime)                                  │
│                                                         │
│ - PreToolUse: Skill — intercepts skill invocations      │
│ - lib/runner.py     — state-machine arbiter             │
│ - lib/gate_*.py     — commit/PR/role gates              │
│ - lib/import_skill.py — SKILL.md → skill.yaml converter │
│                                                         │
│ Identity: runtime + substrate                           │
└────────────────────────┬────────────────────────────────┘
                         │ consumed by
                         ▼
┌─────────────────────────────────────────────────────────┐
│ claude-dev-pipeline (this repo)                         │
│                                                         │
│ - skills/solve-issue/       SKILL.md + skill.yaml       │
│ - skills/review-pr/         SKILL.md + skill.yaml       │
│ - skills/validate-issue/    SKILL.md + skill.yaml       │
│ - skills/check-security/    SKILL.md + skill.yaml       │
│ - skills/suggest-tests/     SKILL.md + skill.yaml       │
│                                                         │
│ Identity: skill corpus — the end-to-end dev loop        │
└─────────────────────────────────────────────────────────┘
```

atomic-gates is **substrate**. claude-dev-pipeline is **corpus**.
Neither is useful without some version of the other (skills need a
runtime; a runtime needs skills). Together they implement the Rules
and Gates thesis end-to-end.

## Relationship to `superpowers`

[`obra/superpowers`](https://github.com/obra/superpowers) is a broader
skill corpus covering brainstorming, TDD, worktrees, planning, and
more. `claude-dev-pipeline` is narrower — focused specifically on the
read-issue → deliver-PR loop.

The two can coexist: install all three (`atomic-gates`,
`superpowers`, `claude-dev-pipeline`) and invoke skills from any of
them. The atomic-gates runner handles all of them via cross-plugin
discovery.

## Development

To add or modify a skill:

1. Edit `skills/<name>/SKILL.md` (the prose source)
2. Run `./scripts/regenerate-skill-yaml.sh` to regenerate the
   corresponding `skill.yaml` skeleton
3. If you want full state-machine enforcement, edit `skill.yaml`
   manually after the regeneration — prune meta sections, refine
   prompts, add output schemas
4. Commit both files

See atomic-gates' guides for the full state-machine authoring
reference:

- [Getting started](https://github.com/lucianfialho/atomic-gates/blob/main/docs/guides/getting-started.md)
- [Authoring state machines](https://github.com/lucianfialho/atomic-gates/blob/main/docs/guides/authoring-state-machines.md)
- [Using with superpowers](https://github.com/lucianfialho/atomic-gates/blob/main/docs/guides/using-with-superpowers.md)
